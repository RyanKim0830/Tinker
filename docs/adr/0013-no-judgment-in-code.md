# ADR-0013: 코드에 판단을 넣지 않고, 지금 필요 없는 확장 포인트를 만들지 않는다

- **Status**: Accepted — 사용자 확정 (작업 지시서의 '확정된 결정')
- **Date**: 2026-10-03

## Context

LLM 응답을 코드가 '고쳐 주는' 순간(thinking 제거, 길이 자르기 등) 문제가 숨는다. 개인 시스템이라 미리 만든 확장 포인트는 짐이 된다.

## Decision

- 자동 추정·임계값 기반 휴리스틱을 넣지 않는다. 코드는 사실과 구현만 다루고 판단은 사람이 한다. (예: 클라이언트는 `message.content` 를 **가공 없이** 돌려준다. thinking 은 서버 옵션으로 끈다.)
- 스트리밍·DB·컨텍스트 한도 처리·인증·미들웨어·Protocol·툴 콜링은 **구현하지 않고** open-items 에 기록만 한다.

## Considered Options

- 응답 후처리 방어 코드: 문제를 숨긴다

## Consequences

- 응답에 이상한 내용이 섞이면 코드가 감추지 않으므로 사람이 보고 서버 설정을 고친다.
- `test_content_is_returned_untouched` 로 고정했다.

## Revisit when

반복되는 사실상의 문제가 생겨 사람이 매번 같은 판단을 하게 되면, 그 판단을 규칙으로 올릴지 논의한다.
