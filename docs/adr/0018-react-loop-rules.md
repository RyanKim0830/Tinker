# ADR-0018: ReAct(툴 콜링) 루프 규칙

- **Status**: Accepted — 사용자 확정 (2026-10-05, 2단계 작업 지시서의 '확정된 결정'). 시스템 프롬프트 부분은 [ADR-0009](0009-system-prompt.md) 를 대체한다. 지시서가 정하지 않은 해석은 아래 "임의로 정한 것"과 open-items 에 따로 적었다.
- **Date**: 2026-10-05

## Context

LLM 이 필요할 때 웹 검색 툴을 부르고, 그 결과(스니펫)를 근거로 답해야 한다. 에이전트 프레임워크(LangChain, LangGraph 등)는 쓰지 않고 직접 구현한다. 서비스는 검색 문제로 터지면 안 된다.

## Decision

방식: **네이티브 툴 콜링** (OpenAI 호환 `tools` / `tool_calls`). 검색어는 LLM 이 툴 호출 인자로 직접 만든다. 구현은 `chat/service.py` 의 루프.

**상한**
- LLM 왕복 상한 `CHAT_MAX_TOOL_ROUNDS` (기본 **2**). 호출한 툴 개수가 아니라 **LLM 왕복 횟수**로 센다.
- 상한에 도달한 **마지막 왕복은 `tools` 를 빼고** 보내서, 지금까지의 결과로 답하게 한다.
- 한 응답에 `tool_calls` 가 여러 개면 **순서대로 전부** 실행한다 (왕복은 1회로 센다).

**실패는 문자열로 돌려준다 (예외로 끝내지 않는다)**
- 검색 쪽 실패(연결 실패, 응답 오류, 결과 0개)는 `tool` 결과 문자열로 LLM 에 돌려준다.
- 잘못된 툴 호출도 에러 내용을 `tool` 결과 문자열로 돌려주고, **왕복 횟수에 포함**한다: `arguments` 가 JSON 이 아님 / `query` 인자 없음 / 등록되지 않은 툴 이름.
- 서버 파싱 실패로 툴 호출 텍스트가 `content` 에 그대로 새어 나오면 **감지하지 않고** 로그에 원문만 남긴다.
- **LLM 자체 실패만** 503(연결) / 502(응답 이상)로 끝낸다. 이때 그 턴은 이력에 저장하지 않는다.

**이력**
- 턴 전체(user, assistant(tool_calls), tool 결과, 최종 assistant)를 저장한다. assistant(tool_calls)와 tool 결과는 **반드시 짝으로** 넣는다 (후속 질문에서 검색 원문을 참조하기 위해). 턴이 끝까지 성공했을 때만 한꺼번에 저장한다.
- 최종 답의 `content` 가 비어 있으면 빈 문자열을 돌려주고 원인은 로그에 남긴다.

**시스템 프롬프트** (ADR-0009 대체): 기존 문구 + 오늘 날짜 + "검색 결과가 있으면 그것을 근거로 답한다."
`너는 사용자의 개인 비서다. 한국어로 짧게 답한다. 오늘 날짜는 2026-10-05이다. 검색 결과가 있으면 그것을 근거로 답한다.` (날짜 형식은 ISO, 임의 선택)

**스니펫**: 상위 5개 (`SEARCH_RESULT_COUNT`), 포맷 `[번호] 제목 (URL)\n내용`.
**타임아웃**: 검색 15초(`SEARCH_TIMEOUT`) / LLM 120초(유지) / CLI 450초.
**로그**(표준 `logging`): 라운드별 content·tool_calls 원문, 생성된 검색어, 검색 결과 개수, 응답 없는 엔진 목록, llama-server timings(+finish_reason).

### 임의로 정한 것 (지시서가 안 정했거나 애매해서)
1. **상한 해석**: `max_tool_rounds=2` 는 "LLM 을 최대 2번 부르고, 2번째는 tools 없이"로 읽었다. 즉 기본값에서 검색은 한 번뿐이고, 잘못된 호출은 재시도 기회 없이 다음 왕복(tools 없음)에서 답하게 된다. "툴을 쓸 수 있는 왕복 2회 + 마지막 답변 1회"(총 3번)로 읽을 수도 있다. 값을 3으로 올리면 그 효과의 일부(검색 2번 또는 재시도 1번)가 난다. → open-items O-23.
2. tools 없이 부른 마지막 왕복에 `tool_calls` 가 와도 실행하지 않고 무시하며 이력에도 남기지 않는다 (짝 없는 호출이 이력에 남으면 다음 요청이 깨질 수 있다). → O-25.
3. `arguments` 가 JSON 이지만 객체가 아니거나, `query` 가 문자열이 아니어도 "잘못된 툴 호출"로 같은 방식으로 처리한다. 빈 문자열 `query` 는 판단하지 않고 그대로 검색에 넘긴다 ([ADR-0013](0013-no-judgment-in-code.md)). → O-24.

## Considered Options

- LangChain/LangGraph 에이전트: 지시로 제외 (직접 구현, 필요하면 나중에).
- 검색어 재작성 단계를 따로 두기: 지시로 제외 (LLM 이 툴 인자로 직접 만든다).
- 검색 실패를 예외(5xx)로 올리기: 서비스가 검색 때문에 터지면 안 된다는 지시로 제외.
- 툴 호출 텍스트 누출 감지·재시도: 지시로 제외 (open-items B).

## Consequences

- 검색이 필요한 질문은 LLM 호출이 2번이라 잡담보다 느리다 (실측 [worklog](../worklog.md)). 한 질문이 서버에서 최대 LLM 2회(각 120초) + 검색 15초 → CLI 타임아웃 450초.
- 이력이 검색 원문까지 쌓여 빨리 커진다. 한도 처리는 하지 않으므로 컨텍스트가 차면 502 로 터질 수 있다 (O-06, 128k 로 완화).
- 코드에 판단을 넣지 않는다: 위 값들(상한, 개수, 타임아웃)은 설정이고 누출 감지 같은 휴리스틱은 없다.

## Revisit when

기본 상한 2 가 너무 빡빡할 때(재시도·다중 검색 필요), 툴이 늘어나 `tools.py` 의 매핑이 복잡해질 때, 컨텍스트 한도 처리(O-06)를 시작할 때.
